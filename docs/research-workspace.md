# 研究・活動ページと執筆の入口

2026年11月10日更新。

## 表示名とタブ

ホームの「記事・記録」は「ニュース・お知らせ」、研究内の「記事・考察」は「研究ノート」に変更した。既存データの種別やIDは移行せず、表示名を対応付ける。

| 画面の名前 | 保存する種別・記録 |
| --- | --- |
| ニュース・お知らせ | Article：ニュース・発表 |
| 研究ノート | Article：研究・実践記事 |
| 実績・評価 | 既存のResult・Evidence等 |
| 資料 | 既存のSource |

研究ページのタブは「概要」「ニュース・お知らせ」「研究ノート」「実績・評価」「資料」。概要は研究を紹介する本文と任意の関連目標を掲載し、記事の抜粋や一覧は掲載しない。地域・課題・技術・メンバーの情報は従来のサイドバーに保持する。

ニュースタブには、その研究に紐づくニュースだけを掲載する。同じニュースをホームの一覧にも表示する。ホームはニュースの種別だけを一覧にし、研究ノートとポートフォリオの活動記録はそれぞれの画面から読む。

## 書く操作

「この研究について書く」を押すと、ネイティブのdialogで以下を選ぶ。

- ニュース・お知らせ：研究が設定済みのニュース執筆画面へ。
- 研究ノート：研究が設定済みのノート執筆画面へ。
- 実施実績：実施実績が選択済みの記録フォームへ。
- 評価結果：評価結果が選択済みの記録フォームへ。
- 資料：資料用の登録フォームへ。

各タブにも入口を設ける。ニュースは「ニュースを書く」、ノートは「研究ノートを書く」、実績・評価は「実績・評価を書く」から二種類を選択、資料は「資料を追加」。概要は概要の編集ボタンを保持する。

ニュースの新規ルートは `#research-news/<研究ID>`、ノートは従来の `#research-note/<研究ID>`。ニュースを研究から作る場合もサーバー側でcontext_idがResearchであることを検証し、研究への関係を必ず追加する。ニュースとノートの下書きは種類・研究IDごとに分かれる。記録フォームも研究IDと記録種別ごとの下書きとし、別種別の下書きが執筆時の選択を上書きしないようにする。

実績・評価・資料を保存したあとは対応するタブを開く。元のArticle、研究概要、過去のResult・Evidenceは自動書換えしない。

## 自由な研究紹介とRDF

基本情報の編集画面にある「もう少し詳しく書く」は、自由なMarkdown本文「研究の紹介」を中心とする。背景・目的などの固定された構成は設けず、見出し・強調・箇条書き・リンク・画像・表・コードを挿入するボタンと「書く／プレビュー」の切り替えを用意する。研究ページの概要にも同じMarkdownレンダラーで表示し、HTMLや危険なURLは除去する。

「関連項目へのリンク」から、その研究に選択済みの登録された地域・課題・技術・資源・メンバーを本文に挿入できる。本文はWikiの既存フィールドにMarkdownをそのまま保存し、RDFの関係は従来の関連項目入力で保持する。文章や本文中のリンクからRDFの関係を自動生成しない。

既存の「目指していること」は削除せず、任意の折りたたみ欄「目標を関連情報として管理する」に保持する。概要では「関連する目標」を開いて確認できる。既存の本文・目標の一括変換は行わない。

## 研究ノートからの整理

研究ノートの本文から段落を選び、実施実績または評価結果として保存する操作は維持する。保存時点の本文と版をSource、引用をEvidence、実績・評価をResultとして対応付ける。引用本文との一致と版はサーバー側で検証する。記事編集後も以前に参照した版の本文を保持する。

- 地図、AI、Markdownの既存JavaScript検証も成功。
- 自由な本文の編集・プレビュー、Markdownの安全な表示、関連項目リンクの挿入、画像・表の挿入ボタンをJavaScriptで検証。Chromeでも既存本文のプレビューと関連項目の候補表示を確認。
- Chrome：概要のみの表示、5つのタブ、執筆内容の選択dialogを確認。ニュースを選んだ後に研究が設定済みのニュース執筆画面へ遷移すること、実績・評価タブのボタンから評価結果を選んで評価フォームが開くことを確認。
