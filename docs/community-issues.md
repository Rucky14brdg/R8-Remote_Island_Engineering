# 地域のお困りごと掲示板

地域の困りごとを、研究テーマが決まる前から登録する。投稿は自己申告の情報であり、確認済みのEvidenceや解決実績を自動生成しない。

## 位置情報の持ち方

位置情報を持つのは **地域・現場（Target）だけ**。イシュー（Issue）は `Target → 抱える → Issue` の関係で現場と結ぶ。同じ現場の座標を各イシューにコピーしない。現場の位置を更新すると、関連するすべてのイシューの地図に反映される。

- 登録済みの施設・道路など：現場を選択する。
- 未登録の場所：「保育所前の坂道」「港の北側の空き地」などの名前で、投稿と同時にTargetを作成できる。正式名称は不要。
- 名前だけ分かる現場：座標を空欄で登録し、後から現場編集で追加する。
- おおよその場所だけ分かる現場：仮の呼び名と概略座標を登録し、「おおよその場所」と明記する。
- 場所が不明・特定の場所を持たない課題：Target未設定でも登録でき、ボード・検索に表示する。
- 複数の現場に関係する課題：複数のTargetと結び、座標が登録された各現場のピンから開ける。

「弓削保育所」は既存TargetのID `保育所` を保持し、表示タイトルを「弓削保育所」とした。利用者が2026年11月10日に提供した座標 `34.252179824041285, 133.1890623153411` をTargetに保存。坂道・駐車場そのものの位置を意味しない。個別の地点が必要な場合は、別のTargetを作り、対応するIssueを結び直す。

## 画面

- 掲示板「地域のお困りごと」：`/#issues` または `/#issues/list`。他タブ共通の背景・フォント・見出し・操作部分を使い、一覧のみ黒板に淡い4色の付箋を貼った表示とする。「掲示板」「地図」「進み具合」を切り替える。付箋の色は装飾であり、状態や分野の分類を意味しない。表示名・説明・場所・研究との関連は既存データから表示し、状態の補足表現のみ親しみやすい言葉に変換する。架空の投稿者や件数は表示しない。
- 状態別ボード：`/#issues/board`。未整理／相談受付／調査・検討中／取組中／解決・一区切りに分けて表示。状態変更は各課題の編集画面から行う。
- 地図：`/#issues/map`。初期状態はピンだけを表示し、右側は空欄。ピンを押すと場所名のリンクを吹き出しに表示し、右側にはそのTargetに紐づく困りごとの付箋だけを表示する。場所名リンクは現場の説明ページへ移動する。地図の空白をタップすると吹き出し・付箋・選択状態を消す。「場所を選ぶ」「選択した場所」の見出しや場所選択欄、常時表示の地図ラベルは置かない。座標だけの地点もTargetのIDで区別し、1件なら1枚。同じ座標の別Targetの課題は混ぜない。検索後は選択現場を維持するが、該当する付箋がなければ空欄。場所未設定の課題は掲示板から探せる。
- 投稿：`/#issue-new`。タイトルが必須。内容・背景・支援希望・投稿者名と立場・研究・地域や現場を任意入力。新しい現場の座標はそのTargetへ保存する。
- 課題の詳細：`/#issue/<id>`。既存研究との関連付け、研究の登録開始、現場へのリンク。研究に関連付けても課題の解決状態は自動変更しない。
- 現場の詳細：`/#entity/<target_id>`。現場の名前・概要・地図・関連する困りごと・研究を表示する。
- 現場の登録／編集：`/#place-new`、`/#place-edit/<target_id>`。名前・概要・位置・精度を登録・編集する。座標は任意。

投稿中の入力はlocalStorageへ下書き保存する。既存課題の版が変わった場合、古い下書きは自動適用せず、APIも古い版での保存を409で拒否する。現場の編集もrevisionで競合を検出し、既存の課題・研究・Wikiなどの関係は保持する。

## APIと保存

- `GET /api/issues`：課題と、関係するTarget（名前・座標・位置の精度を含む）を返す。課題自体の緯度・経度は返さない。
- `POST /api/issues`：課題を保存する。新規現場の入力は `new_target`、`new_target_latitude`、`new_target_longitude`、`new_target_precision`。座標指定時には現場名が必要。入力と参照先を検証してから、現場と課題をまとめて保存する。Issueへの直接の`latitude`／`longitude`入力は拒否する。
- `GET /api/places`：Targetの一覧、座標、編集用revisionを返す。
- `POST /api/places`：Targetを新規登録／編集する。編集は `target_id` と `expected_revision` が必要。名前と座標を変更しても、既存IDと関係を保持する。

既存のIssue、Target、Researchをそのまま利用し、別の掲示板DBは作成しない。ResearchとIssueの関係は `解決を試みる`。投稿者の名前・立場からUserや認証権限を自動作成しない。既存Issueに課題状況がなければ「未整理」と表示する。

## 地図と検証

[Leaflet 1.9.4](https://leafletjs.com/examples-v1.html) をローカルに同梱し、背景地図は[OpenStreetMap標準タイル](https://operations.osmfoundation.org/policies/tiles/)を使用。外部に投稿本文を送る処理や住所検索はない。背景地図の読込にはオンライン接続が必要。現場ピンは外部の画像に依存しないHTMLで描画する。

アイコン用の全体CSSがLeafletのSVGを19pxに制限していたため、地図用SVGを対象外に修正した。HTMLの静的アセットURLにはファイル更新時点を付け、修正後のスクリプト・CSSを再取得できるようにした。

` .venv/bin/python -m unittest discover -s tests -v `：71件成功。座標を持つ現場の共有・更新、未登録現場と課題の同時保存、位置不明での投稿、複数現場への関連、座標0、直接の課題座標の拒否、不正参照での部分保存防止、競合検出、既存知識の保持を含む。JavaScriptはNodeで構文確認。Chromeで「弓削保育所・4件」の施設ピンと背景地図の表示を確認。

現状はローカル試作。外部公開に必要な認証・編集権限・公開前確認、コメント・通知・担当者管理、変更履歴は未実装。

場所選択の検証：`node tests/issue_map_selection.cjs` で施設ごとの分離、座標だけの地点で1件表示、同一座標・別IDの分離、複数施設共通の課題、0件、検索後の選択保持を確認。Chromeで保育所4件→学校のピンをクリックして1件への切替を確認。Python既存71件も成功。
