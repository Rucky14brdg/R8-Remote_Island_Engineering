# 入力GUIの第1試作

2026年11月4日。「研究・活動の登録を優先」という意向に合わせ、ポートフォリオから登録・編集へ進む流れを作り直した。

## 確認する画面

- `/`：人物ごとのプロフィール、参加している研究・活動、所属組織の活動。
- `/#editor`：研究・活動の入力。名称だけでも保存可能。
- `/#activities`：全研究・活動の検索・一覧・編集。
- `/#people`：研究者・実践者一覧。
- `/#explore`：地域・課題・技術・資源から取り組みを探す。
- `/advanced`：従来の画面。AI探索、記事の執筆、出典・成果等の詳しい編集を維持。

開発サーバーの起動例：

```sh
.venv/bin/python -m uvicorn app:app --host 127.0.0.1 --port 8765
```

## 入力の流れ

1. 名称、短い概要、活動時期を入力する。名称以外は任意。
2. 地域・課題、技術・資源を、既存候補から選択する。新しい名称もその場で追加できる。
3. メンバーと活動内の役割を入力する。個人・組織・集団を選べる。
4. 必要に応じて「もう少し詳しく書く」を開き、目標、背景・活動内容、関連リンクを書く。
5. ライブプレビューまたはプレビューダイアログで確認し、保存する。

ブラウザ内の下書きと、データベースへの保存を分離した。下書きは研究者・活動ごとに保持し、再読み込みやページ移動後に再開できる。削除直前の下書き1件は復元可能。保存すると実際の既存RDFデータへ反映する。

名称は表示するタイトルとして保存し、既存の識別子を変更しない。資源や人物の名称に空白・記号が含まれる場合は、表示名を保持して安全な識別子へ変換する。新規候補の作成、研究との関連、メンバーの役割はまとめて検証してから保存する。不正なメンバーや同名の別種類がある場合、途中のデータは書き込まない。

研究の編集で既存の出典や別経路の目標を削除しない。根拠付きの役割を削除しようとする場合は詳細編集へ案内する。単なる関連URLを、確認済みの根拠資料とは扱わない。

## 今回試してほしい点

- 名称と概要から書き始める順序が自然か。
- 地域・課題・技術・資源を入力する項目の量が適切か。
- 候補を選ぶ方法と、新規の名前を追加する方法が分かるか。
- 人物・組織と役割を同じ場所で入力する方法が使いやすいか。
- 詳しい情報を折りたたむ構成と、プレビューの位置が合っているか。

## 検証と範囲

既存の設計検証12件と、用途別保存処理・APIの検証11件、計23件を実行した。テストは一時ディレクトリで行い、実データは変更していない。

Chromeでポートフォリオと登録画面の表示を確認し、名称入力によるライブプレビュー更新、既存候補の追加、再読み込みによる下書き復元、プレビューダイアログ、下書きの削除・復元導線を確認した。保存処理はAPIのテストで検証し、ブラウザから実データへ試験用の活動は登録していない。

画面の認証・権限制御は未実装。左下の人物選択は表示・入力対象の切替であり、ログインではない。進捗・成果・資料の専用GUIは後述のとおり追加済み。資料からの一括登録、履歴・業績等のプロフィール拡張は次の検討範囲。狭い画面用のレイアウトは実装済みだが、実機での操作は未検証。

## 公開側の入口

初期表示とロゴのリンク先を記事・記録へ変更した。人物を選択していない場合も、一覧・本文・著者・関連項目を参照できる。サイドメニューを「読む・探す」と「自分の記録」に整理し、記事画面の右上にはポートフォリオへの入口を置いた。`node tests/frontend_public_home.cjs`で、人物未選択時の初期表示、記事本文、著者・関連項目へのリンク、著者名での検索を確認した。

この変更は公開側のGUIの入口を整えるものであり、認証・編集権限を実装するものではない。認証機能を追加する際は、記事の閲覧と、ログインを要する編集・保存APIを区別する必要がある。

## 進捗・実績・根拠資料の入力

研究・活動の詳細画面の「進捗・実績・根拠資料」→「記録を追加」から入力する。既存の研究・活動の編集画面右側にも「記録を追加する」ボタンを置いた。新規研究は先に名称等を保存する。「詳しい記録は、あとから」「詳細編集から追加できます」という曖昧な案内は置き換えた。

- 種類は進捗／実施実績／評価結果／根拠資料のみ。内容はMarkdownで記入でき、活動時期と記録者を選べる。
- 根拠は入力者自身の記録、新しい資料、登録済みの資料から選ぶ。資料には名称・URL・発行時点・メモを登録できる。ファイルアップロード機能は含まない。
- 外部資料に基づく記録では、該当箇所と確認状況を指定する。資料だけの登録も可能。
- 入力者自身の記録はSourceとして出典を明示し、外部資料との照合は「未確認」とする。資料を登録しただけで、検証済みの成果は作らない。
- 保存API `/api/portfolio/activity-record` はRDFへ反映する。進捗はEvidence、実施実績・評価結果はResult＋Evidenceとして追加する。既存の記録や研究の基本情報は上書きしない。活動時期・資料の発行時点・登録時点は別々に保持する。
- 入力は研究ごとのブラウザ内下書きに保存し、追加ボタンを押すまでDBへ書き込まない。基本情報の編集中に記録を追加しても、そのフォームの入力内容は保持する。

一時ディレクトリによる保存・検証・APIのテストを追加し、全41件が成功。フロントエンドでは追加導線、実績の根拠表示、資料の重複排除とMarkdown表示を確認した。Chromeで詳細画面からフォームを開き、進捗と資料のみの入力項目の切り替えを確認した。実データへの試験用記録の登録は行っていない。

## 研究ページの構成変更

研究ページは「概要／記事・考察／実績・評価／資料」のタブ構成へ変更した。上記の進捗入力を主とする配置は、この変更により更新されている。主な入口は「この研究について書く」。記事の閲覧画面から、本文の段落を押して実施実績・評価結果として整理できる。詳しい構成と検証は [research-workspace.md](research-workspace.md) を参照。
